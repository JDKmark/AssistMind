## 计划：phase7 切块修复 — 孤儿标题 chunk 消除 + 表格上下文前缀

### 背景（链路逐步排查结论）
mall 集优化后（faith 0.972 / cp 0.877 / cr 0.824），逐条对账 recall<0.7 的 9 个样本，根因集中在**切块层**，是上一轮检索优化未覆盖的同类问题：

1. **孤儿标题 chunk（全库 51 个）**：`chunk_text` 对「标题行 + 紧跟表格/fence」处理时，标题行被 flush 成独立 chunk（如 `## 2. 订单状态流转` 单独成块），内容为空壳——浪费 top-8 检索槽位，且表格脱离标题语义
2. **GT 跨 chunk 事实**：GT 多步事实（Windows 安装三步 / Redis 三文件 host）分散在多个 chunk，top-8 覆盖不全 → recall=0/0.5（如「订单状态 0-5」枚举表被切碎）
3. **表格无上下文前缀**：表格块只有 `| 状态值 | 含义 |` 表头无标题，embedding/rerank 语义弱 → 排名低

根因均在 `chunking.py` 的 `_chunk_markdown`（标题行 flush 逻辑 + 表格 emit 无前缀），一处修复覆盖三类问题。

### 改动（Lite 档：单模块 chunking.py + 测试 + 重灌 + 评估）
1. **标题 pending 机制**（chunking.py `_chunk_markdown`）：标题行不再独立 flush 成块，随下一个结构块（表格/fence）或文本缓冲合并成块
2. **表格块拼接 `## {section_title}` 前缀**：表格单独成块时保留标题语义上下文
3. **test_chunking.py**：更新受影响断言 + 新增孤儿标题/表格前缀用例

### 验证（按序）
1. 单测：`pytest tests/unit/test_chunking.py` + 全量 `-k "not integration"` 无回归；mall KB 孤儿标题 51 → 0（诊断脚本校验）
2. 重灌：`seed_mall_kb.py --reset`（text 变化必须重建 Qdrant 向量 + BM25）
3. 重跑 mall RAGAS：`run_eval.py app/data/eval_mall_qa.json`，对比 ds5 基线——预期 **context_recall 0.824 → ≥0.85**、faithfulness 不回退（≥0.95）
4. 更新 README/demo-script 数字 + 提交
