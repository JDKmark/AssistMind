### C. Chat 页工具结果卡片化渲染

**现状**：`tool_result` 事件目前只提取 ticketId，丢弃了 result 数据（Chat/index.vue:282-291）；工具结果以截断 JSON 文本展示（toolArgsText）。

**改动 `frontend/src/views/Chat/index.vue`**：

1. **`handleEvent` tool_result 分支**：把 `data.result` 存到 `tc.result`（当前只存 ticketId）
2. **新增解析函数** `parseToolResult(tc)`：按工具名 + 结果形状识别卡片类型，返回结构化数据：
   - `query_order` → dict 含 order_sn/status → 订单卡片（订单号/状态/实付/物流单号/商品明细 items）
   - `query_logistics` → list 含 ts/content → 物流轨迹卡片（按时间正序列出）
   - `query_product` → dict 含 id/name → 商品卡片（名称/规格/价格/库存/服务标签）
   - `apply_refund` → dict 含 refund_id → 售后结果卡片（售后单号/状态/提示）
   - 其他/不可解析 → 返回 null（保持现状 JSON 文本回退）
3. **模板**：在 tool-item 下方，对可解析的工具结果渲染 `el-descriptions`（仿 Admin 页 border size="small" 风格）；query_logistics 用简单时间线列表（el-timeline 或纯 div 均可，Element Plus 优先）
4. **样式**：卡片区与工具调用行分隔，视觉轻量

**测试 `frontend/tests/unit/Chat.spec.js`**：
- stubs 补 `el-descriptions` / `el-descriptions-item`（复用 Admin.spec.js 的 stub 模式）
- 新增 2 个用例：query_order 事件 → 渲染订单卡片（含订单号/状态）；query_logistics 事件 → 渲染物流轨迹卡片（含轨迹内容）
- 现有用例保持全绿（无工具结果时行为不变）
