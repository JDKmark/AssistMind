# OPS-004：微服务故障诊断方法论

## 诊断顺序（先全局后局部）
1. 确认告警：哪个服务、哪个指标、严重级别
2. 分析指标：错误率、延迟、CPU、内存、QPS 的异常形态（突增/爬升/周期性）
3. 检索日志：按服务与关键字定位异常堆栈与错误消息
4. 核对变更：故障前最近一次发布或配置变更往往是根因
5. 参考案例：检索历史故障案例手册，匹配相似症状

## 关键判断
- 下游服务异常会传导到上游：出现上游报「Remote call failed」时要检查下游
- 指标异常形态有提示性：陡增多为突发流量/变更，爬升多为资源泄漏
- 变更先于故障出现时，优先怀疑变更引入

## 输出要求
诊断报告需包含：症状 → 证据（指标/日志/变更） → 根因 → 恢复建议，证据要可回溯。
